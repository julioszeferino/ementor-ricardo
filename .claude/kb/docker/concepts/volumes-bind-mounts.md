# Volumes and Bind Mounts

> **Purpose**: Persist database data across container recreation and share code/config between host and containers
> **Confidence**: 0.95
> **MCP Validated**: 2026-10-09

## Overview

A **named volume** is storage managed by Docker (`docker volume ls`); it outlives the
container and is the preferred way to persist data generated by containers (Postgres
data dirs). A **bind mount** maps a host path into the container; use it for things you
edit on the host (DAGs, dbt project, init scripts). Compose prefixes named volumes with
the project name (`<project>_pgdata`) and only deletes them on `docker compose down -v`.

## The Pattern

```yaml
services:
  postgres:
    image: postgres:18
    volumes:
      - pgdata:/var/lib/postgresql                       # named volume (PG 18+ path)
      - ./postgres/initdb:/docker-entrypoint-initdb.d:ro # bind mount, read-only
  airflow-scheduler:
    image: apache/airflow:3.3.2
    volumes:
      - ./dags:/opt/airflow/dags                         # edit on host, picked up live
      - type: bind                                       # long syntax
        source: ./dbt
        target: /opt/dbt
        read_only: true
        bind:
          create_host_path: false                        # fail instead of creating ./dbt

volumes:
  pgdata: {}                                             # declared => managed by Compose
```

## Quick Reference

| Input | Output | Notes |
|-------|--------|-------|
| `pgdata:/path` (declared top-level) | Named volume `<project>_pgdata` | Survives `down`; removed by `down -v` |
| `./dir:/path` | Bind mount (relative to compose file) | Host dir auto-created if missing (default) |
| `./dir:/path:ro` | Read-only mount | Init scripts, configs, dbt project in prod-like runs |
| `/path` only | Anonymous volume | Hard to find later; avoid |
| Empty named volume over image dir | Image content copied into volume | Not done for bind mounts |
| `docker volume prune` | Removes unused **anonymous** volumes | `-a` removes unused named ones too |
| Postgres 18+ | Mount at `/var/lib/postgresql` | PGDATA is `/var/lib/postgresql/18/docker` |
| Postgres <= 17 | Mount at `/var/lib/postgresql/data` | Older tutorials use this path |

## Common Mistakes

### Wrong

```yaml
services:
  postgres:
    image: postgres:18
    volumes:
      - /var/lib/postgresql/data        # anonymous volume + pre-18 path
      - ./pgdata:/var/lib/postgresql    # bind-mounting the DB data dir to the host:
                                        # slow on macOS, UID/permission issues
```

### Correct

```yaml
services:
  postgres:
    image: postgres:18
    volumes:
      - pgdata:/var/lib/postgresql
volumes:
  pgdata: {}
```

```bash
docker compose down        # data kept
docker compose down -v     # data DELETED -- next start re-runs initdb scripts
```
